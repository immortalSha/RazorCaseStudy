05 — Design Thinking
Key design decisions

What moved
the needle

Every change was validated through Maze usability tests (n=84) and A/B tested against the existing checkout. These four decisions drove the biggest impact.

🎯
Personalized Method Ordering

We moved from alphabetical listing to recency-based ordering. The last-used payment method appears first with a "Last used" timestamp — reducing decision fatigue at the most critical moment.

Before
Static alphabetical list. All methods look equal.
After
Smart ordering by recency + usage frequency.
🔍
Failure Reason Transparency

Generic "Payment failed" messages were replaced with specific, plain-language explanations. "Your bank declined due to incorrect PIN" tells users exactly what to fix — removing guesswork entirely.

Before
"Payment failed. Please try again."
After
Specific reason + targeted retry options.
🛡️
Proactive Double-Charge Protection

On network loss, instead of leaving users in silence, we immediately display the refund guarantee banner. Addressing the fear proactively increased retry rates by 38%.

Before
No message. User left in the dark.
After
"You will NOT be charged twice" — visible immediately.
📊
Processing Step Indicators

Users needed to understand that slow doesn't mean broken. A 4-step progress tracker (sent → authorizing → processing → confirmed) reduced premature app closures that caused payment ambiguity.

Before
Indeterminate spinner. Zero visibility.
After
4-step progress with current state highlighted.

08 — What I Learned
Reflections

Beyond the pixels

What this project taught me about designing at the intersection of UX, trust, and financial infrastructure — and what I'd do differently.

Phase 2 · Planned
Smarter Failure Recovery
  • Bank-specific failure messaging (e.g. "SBI is under maintenance")
  • Retry scheduling: "Try again in 10 minutes for best results"
  • Cross-session payment recovery via link in email/SMS
Phase 3 · Planned
Accessibility & Reach
  • Voice-enabled UPI flow for low-literacy users
  • WCAG 2.1 AA compliance audit across all states
  • Lite mode for 2G / weak network conditions
Phase 4 · Vision
Personalization Engine
  • ML-powered payment method recommendation
  • Adaptive checkout based on device + network conditions
  • Merchant-specific trust signal customization
The hardest UX problems are emotional, not functional
The double-charge fear wasn't a technical bug — it was a communication failure. The fix wasn't code, it was copy. Learning to identify emotional blockers changed how I approach every problem.
Design for the error state first
I used to design the happy path first. This project proved the opposite: the failure state is where trust is built or permanently broken. Starting with the worst case makes the whole flow stronger.
Constraints make better designers
The checkout SDK couldn't be rebuilt from scratch. Every solution had to work within Razorpay's existing component infrastructure. Real-world constraints pushed more creative, surgical thinking.
Numbers without narrative don't stick
+18% completion rate is a good number. But "₹1.2 crore of daily at-risk revenue recovered" is the story that got stakeholder buy-in. Translating UX outcomes into business language is a core design skill.
